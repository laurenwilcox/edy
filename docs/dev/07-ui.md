## 1. Как интерфейс встроен и отдаётся

### 1.1. `internal/ui/ui.go` (26 строк)

```go
//go:embed static
var static embed.FS

func Handler() http.Handler {
	sub, _ := fs.Sub(static, "static")
	files := http.FileServer(http.FS(sub))
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("X-Frame-Options", "DENY")
		w.Header().Set("Content-Security-Policy", "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' data: blob:; frame-ancestors 'none'")
		files.ServeHTTP(w, r)
	})
}
```

- Папка `internal/ui/static` целиком встраивается в бинарник через `embed`. Сейчас в ней один файл
  `index.html`. Любой новый файл в `static/` (картинка, css) тоже автоматически окажется в бинарнике
  и будет доступен по `/<имя>`.
- `http.FileServer` отдаёт `index.html` на запрос `/`. Сборки фронтенда нет: правите файл → `go build`
  → готово. Для разработки достаточно перезапустить процесс (файл встраивается на этапе компиляции,
  «горячей» перезагрузки нет).
- Заголовки безопасности ставятся на **каждый** ответ статики (подробно — раздел 11).

### 1.2. Где монтируется

`internal/app/app.go:171` — `mux.Handle("/", ui.Handler())`. Полная таблица маршрутов сервера
(`app.go:166-171`):

| Префикс | Обработчик | Что это |
|---|---|---|
| `/v1/` | `omniroute` router | OpenAI-совместимый API (чат интерфейса стримит отсюда) |
| `/healthz` | router | проверка живости |
| `/api/` | `api.Handler` | JSON API интерфейса (все требуют `Authorization: Bearer <token>`) |
| `/mcp` | MCP-сервер Edy | для внешних агентов |
| `/` | `ui.Handler()` | эта страница |

Статика **не** требует токена (страница публична на localhost), а все данные — только через `/api/` с токеном.

### 1.3. Как страница получает токен

- `app.Server.URL()` (`app.go:88`) возвращает `http://<addr>/#token=<router_token>`.
- `edy ui` (`cmd/edy/main.go:78`) поднимает сервер и открывает этот URL в браузере.
- Окно Wails (`cmd/edy-app/main.go:67,74`) открывает тот же URL с добавкой `&app=1`.
- Токен находится в `#`-части: браузер не отправляет её на сервер и в логи.
- JS при старте (`index.html:874-884`) читает `token` и `app` из `location.hash`, кладёт их в
  `sessionStorage` (`edy-token`, `edy-app`) и **стирает хэш** через `history.replaceState`. После
  перезагрузки вкладки токен берётся из `sessionStorage`; после закрытия вкладки — пропадает.
- Если токена нет — показывается красная плашка `#auth` («Нет токена доступа. Откройте интерфейс
  командой edy ui.», `index.html:868`) и инициализация прекращается (`index.html:3125`).

Сам токен — значение настройки `router_token` в SQLite (`app.EnsureToken`, `app.go:62`), формат
`edy-<48 hex>`; копия пишется в `<home>/router.token`.

## 2. Общая раскладка экрана

```
┌──────────────┬─────────────────────────┬──────────────────────────────────────┐
│ nav.side     │ aside.drawer (выезжает) │ main.chat                            │
│ (меню, 236px)│ ширина min(500px,42vw)  │ .chat-head (режимы, модель, «Новый») │
│              │ .panel-head + .panel-body│ .orch-bar (проект/исполнитель/резерв)│
│              │   section#p-…           │ #messages | #orch-messages | #board  │
│              │                         │ #composer-wrap (ввод)                │

```

DOM-порядок (`index.html:429-856`): `.app` → `nav.side#side` → `aside.drawer#drawer` → `main.chat`.
Фон — `.aurora` (три размытых «пятна», анимация `drift`, `index.html:42-51, 427`).

- **Меню** `nav#side` (`index.html:431-449`):
  - бренд «E / Edy / ИИ-IDE»;
  - `#go-chat` «💬 Чат» — закрывает панель и фокусирует поле ввода;
  - группа «🔌 Провайдеры» `#grp-providers` (раскрывающаяся, по умолчанию открыта): «Подключённые»
    (`p-list`), «Добавить» (`p-add`), «Расходы» (`p-usage`), «Подключение» (`p-connect`);
  - пункты «🗂 Проект» (`p-project`), «🔀 Git» (`p-git`), «👥 Команда» (`p-team`),
    «🧩 MCP-серверы» (`p-mcp`), «🤖 Агенты» (`p-agents`, со счётчиком `#agents-running` «N работает»);
  - подвал `.side-foot`: зелёная пульсирующая точка, **статичный** текст «OmniRoute работает» и
    `#foot-providers` («N провайдер(а), M моделей»).
- Любой элемент с атрибутом `data-open="p-…"` открывает соответствующую панель — это делается одним
  делегированным обработчиком на `document` (`index.html:960-963`). Поэтому кнопку открытия панели
  можно поставить где угодно (например, «＋ Добавить провайдера» в `p-list`).
- **Выезжающая панель** `aside#drawer`: `.drawer` шириной 0 → `.drawer.open` шириной
  `min(500px, 42vw)` с анимацией. Внутри `.panel-head` (заголовок `#panel-title`, кнопка ✕
  `#panel-close`) и `.panel-body` с секциями `section#p-*`. Видна ровно одна секция (атрибут `hidden`).
- **Чат** `main.chat` — всегда виден, занимает остаток ширины (`flex:1`).
- **Мобильная/узкая раскладка** (`@media (max-width: 900px)`, `index.html:409-420`): меню становится
  фиксированной выезжающей шторкой (`.side.show`), появляется кнопка ☰ `#menu-toggle`, панель
  открывается поверх всего экрана (`position: fixed; inset: 8px`), формы — в одну колонку.
  Касание вне меню закрывает его (`index.html:969-971`).

## 3. Панели (разделы меню) — подробно

Регистрация панелей — два словаря (`index.html:943-944`):

```js
const titles  = { "p-list": "Подключённые провайдеры", "p-add": "Добавить провайдера", "p-usage": "Расходы", ... };
const loaders = { "p-list": loadProviders, "p-add": () => {}, "p-usage": loadUsage, "p-connect": loadConnect,
                  "p-project": loadProjects, "p-git": loadGit, "p-team": loadTeam, "p-mcp": loadMCPServers, "p-agents": loadAgents };
```

`openPanel(id)` (`index.html:946`) скрывает все секции, кроме нужной, подсвечивает пункт подменю,
ставит заголовок, открывает drawer, запоминает панель в `localStorage["edy-panel"]` и вызывает
загрузчик. При следующем запуске последняя панель открывается снова (`index.html:3139-3140`).
`closePanel()` (`index.html:955`) закрывает и стирает `edy-panel`.

### 3.1. `p-list` — «Подключённые провайдеры» (`index.html:460-463`)

**Пользователь видит:** карточку на каждого провайдера и кнопку «＋ Добавить провайдера».

Карточка (`providerCard`, `index.html:1048`), `div.card.lift[data-provider=<name>]`:
- имя + бейдж типа (`kindNames`: CLI / Anthropic / OpenAI-совм. / Веб-чат; у CLI — `.badge.cli`);
- кнопки: для `web` — «Войти» (`webLogin`) и «Проверить» (`webCheck`); для остальных — «Модели»
  (`openModelEditor`); у всех — «Удалить» (`removeProvider`);
- строка цели: для CLI — команда запуска, для web — URL сайта + тип браузера, для API — base_url;
- чипы моделей `provider/model` — клик открывает чат с этой моделью (`chatWith`);
- блок возможностей «Умеет:» (`capsBlock`, `index.html:1028`) — кнопки-теги `.cap` из каталога
  `GET /api/caps`. Клик переключает тег и сохраняет `PUT /api/providers/{name}/caps`. Тег `mcp`
  заблокирован, если `p.can_mcp == false`. Если теги автоматические — подпись «· автоматически»,
  иначе кнопка «Сбросить» (отправляет `caps: null`);
- для `openai`/`anthropic` — блок ключей (`keysBlock`, `index.html:1074`): список ключей с меткой
  (и бейджем «отключён», если ключ отключён по лимиту), кнопка «Удалить» (`removeKey`), форма
  «метка + API-ключ + Добавить» → `POST /api/providers/{name}/keys`;
- для `web` — бейдж статуса `span.status[data-status=<name>]`, заполняется `refreshWebStatus`.

**Редактор моделей** (`openModelEditor(name, autoLoad)`, `index.html:1098`) встраивается в карточку
блоком `.picker`: поле «модели через запятую», для не-CLI — кнопка «Загрузить с сервера»
(`GET /api/providers/{name}/remote-models`), после загрузки — фильтр и список чекбоксов
(не более 400 видимых), «Сохранить» → `PUT /api/providers/{name}/models`, «Отмена». Поле и
чекбоксы синхронизируются через общий `Set chosen`. Если провайдер API добавлен без моделей,
редактор открывается автоматически с `autoLoad=true`.

**Статус веб-чатов** (`refreshWebStatus`, `index.html:1009`): `GET /api/web/status` → для каждого
бейджа `[data-status]` ставит класс `status <state>` и текст из `stateText`. Пока есть состояния
`login_open`/`checking` и drawer открыт — повторяет опрос каждые 2 с (`statusTimer`). Поле `account` попадает в `webAccounts` и в
`[data-account]` карточки: «👤 email» или «используем без аккаунта».

### 3.2. `p-add` — «Добавить провайдера» (`index.html:465-520`)

Форма `#add-form` с переключателем `.seg` из трёх режимов (`data-mode`): «Утилита по подписке»
(`cli`), «API-ключ» (`api`), «Веб-чат» (`web`). Режим хранится в `addMode`.

Поля помечены `data-for="…"` — список режимов, в которых поле видно. Особые значения:
`cli-custom` (видно только когда выбрана «Своя утилита…»), `api-custom` («Другой сервис…»).
Видимость считает `syncForm(fill)` (`index.html:1212`).

| Поле (name) | data-for | Назначение |
|---|---|---|
| `preset` (select) | cli | готовый профиль CLI (`presets.cli`) + «Своя утилита…» (value="") |
| `command` | cli-custom | своя команда, аргументы через пробел, подстановки `{model}`, `{prompt}` |
| `site` (select) | web | сайт веб-чата (`presets.web`) |
| `browser` (radio chromium/chrome) | web | изолированный Chromium или «Мой Google Chrome»; chrome блокируется, если `GET /api/web/browsers` сказал, что Chrome не найден (`#chrome-note`) |
| `service` (select) | api | сервис (`presets.api`) + «Другой сервис…» |
| `kind` (select openai/anthropic) | api-custom | формат API для своего сервиса |
| `base_url` | api | адрес API (подставляется из пресета) |
| `secret` (password) | api | ключ; `#key-link` — ссылка «получить ключ ↗» из `pr.key_url` |
| `name` | все | имя = префикс модели; автоподстановка: `claude-code→claude`, `antigravity→agy`, web → `<site>-web` |
| `models` | cli api | модели через запятую |
| `price_in`, `price_out` | api | $ за 1M токенов |

`#preset-hint` — подсказка: команда запуска пресета, правила подстановок, для web — предупреждение
о лимитах (`min_interval_sec`, `daily_limit`) и о риске блокировки аккаунта.

Отправка (`index.html:1263`): собирает тело в зависимости от режима → `POST /api/providers`; если
введён ключ — дополнительно `POST /api/providers/{name}/keys` с меткой «основной»; затем открывает
`p-list`. Если сервер ответил **409** с `data.install` (CLI-утилита не установлена) — показывается
`#install-box` (`offerInstall`, `index.html:1300`): текст ошибки, команда установки, кнопка
«Установить» → `POST /api/install {preset}`; вывод — в `pre.log`; после успеха форма отправляется
заново (`form.requestSubmit()`).

Значения по умолчанию после загрузки пресетов (`fillPresetSelects`, `index.html:1254`):
CLI = `antigravity`, API = `anthropic`.

### 3.3. `p-usage` — «Расходы» (`index.html:522-550`)

- `#spent` — потрачено сегодня (крупная цифра `.stat`), `#budget-text` — «из $X дневного лимита».
- `#meter` — полоса прогресса, класс `warn` при ≥80 %, `over` при ≥100 %; анимация ширины
  запускается через двойной `requestAnimationFrame`.
- `#budget-form` — поле `usd` → `PUT /api/budget {usd}` (0 = без лимита).
- Таблица `#usage-rows`: Агент (`client`, т.е. заголовок `X-Edy-Client`), Модель, Запросы,
  Стоимость; в `title` строки — токены.
- Таблица `#model-stats` (`loadModelStats`, `index.html:1354`, `GET /api/stats/models?days=30`):
  модель, успех `% (s/a)` с цветом (≥70 зелёный, ≥40 жёлтый, иначе красный), цена за успешную
  задачу (или «подписка», если стоимость 0), всего $.

### 3.4. `p-connect` — «Подключение» (`index.html:767-797`)

- `#base-url` — base URL OpenAI-совместимого API Edy (`GET /api/info` → `base_url`).
- `#token-view` — токен, скрыт точками; `#show-token` переключает «Показать/Скрыть».
- Кнопки `[data-copy="base_url"|"token"]` копируют `info[...]` в буфер (`navigator.clipboard`).
- `#mcp-snippets` (`renderMCP`, `index.html:1388`) — три готовые команды для подключения MCP Edy
  к внешним агентам для **текущего проекта** (`#project`):
  1. Claude Code через HTTP: `claude mcp add --transport http edy '<mcp_url>?project=…' --header 'Authorization: Bearer <токен>'`
     — на экране вместо токена `<токен>`, при копировании подставляется настоящий;
  2. Claude Code через stdio: `claude mcp add edy -- '<edy_path>' mcp -project '<project>'`;
  3. JSON `mcpServers` для Gemini CLI / Cursor / Claude Desktop.
  Экранирование для shell — `shq()` (одинарные кавычки).

### 3.5. `p-project` — «Проект» (`index.html:552-622`)

Самая насыщенная панель. Сверху две кнопки: `#open-board` «📋 Доска задач» (закрывает панель и
включает режим «Доска») и `#open-files` «📂 Файлы проекта» (`openFiles`).

Блоки по порядку:

1. **Добавить проект** — `#project-form` (поле `path`) → `POST /api/projects {path}`. После успеха
   новый проект становится текущим; если `p.ready == false`, тост с `p.problem` красный.
2. **Список проектов** `#project-list` (`renderProjects`, `index.html:2740`): карточка с именем,
   бейджем ветки (или «папка» для не-git), статусом (`идёт задача` / `ждёт решения` / `готов` /
   `не готов`), путём, текстом проблемы; кнопки «Выбрать» (меняет `#project`) и «Убрать»
   (`removeProject` → `DELETE /api/projects?path=`). Текущий проект — `.card.current`.
3. **Снимки (Shadow Git)** `#checkpoints` (`loadCheckpoints`, `index.html:2879`,
   `GET /api/projects/checkpoints?path=`): строки `.cp` «№N сообщение время [Откатить сюда]».
   Самый свежий (i=0) без кнопки. Откат — `restoreCheckpoint` → `POST /api/projects/restore {path,id}`.
4. **Память проекта** (`loadMemory`, `index.html:2763`):
   - `#mem-search` (поле `q`) → `GET /api/memory?project=&q=`;
   - `#mem-list` — до 60 заметок: бейдж вида (`noteKind`: факт/урок/задача/заметка; урок — красный,
     задача — голубой), дата, источник (`из задачи` для `task:*`, `внешний агент` для `mcp:*`),
     текст; кнопки 📌/📍 (закрепить/открепить → `PUT /api/memory/{id} {project, pinned}`) и ✕
     (`DELETE /api/memory/{id}?project=`);
   - `#mem-add` — select `kind` (fact/lesson/note) + `text` (≤400) → `POST /api/memory`.
5. **Скиллы** (`loadSkills`, `index.html:2790`, `GET /api/skills?project=`): имя, бейдж «общий»/
   «проект», описание, раскрывающийся текст, «Удалить» (`DELETE /api/skills?scope=&name=[&project=]`).
   Форма `#skill-form` внутри `<details class="skill-add">`: `scope` (project/global), `name`,
   `description`, `body` → `POST /api/skills`. Формат совместим с Claude Code (`<имя>/SKILL.md`).
6. **Карта проекта** `#ctx-form` + `#ctx-out` (`loadContext`, `index.html:2826`):
   - без запроса — `GET /api/projects/context?path=&q=` возвращает «скелет» проекта (то, что видят
     агенты); с запросом — BM25-поиск по коду;
   - чекбокс `semantic` «по смыслу» → `GET /api/semantic/search?project=&q=`: вывод в виде
     `── path · symbol (строки a–b)` + первые 12 строк куска с номерами; `r.note` — пояснение
     (например, что индекс не готов и использован поиск по словам).
7. **Поиск по смыслу** `#sem-card` (`loadSemantic`, `index.html:2851`):
   - `#sem-form` поле `model` с `datalist#sem-models` (подсказки: модели провайдеров `openai`, в имени
     которых есть `embed`, плюс `<provider>/` как заготовка) → `PUT /api/semantic {model}`
     (пустая строка — выключить);
   - `#sem-index` «Построить индекс» → `POST /api/semantic/index {project}`; кнопка выключена,

## 4. Область чата: режимы Чат / Оркестратор / Доска

Шапка `.chat-head` (`index.html:804-814`): ☰ `#menu-toggle` (только на узком экране), сегмент
`#mode-seg` с кнопками `data-chat-mode="chat|orch|board"`, select `#model`, кнопка `#new-chat`
«＋ Новый».

`setChatMode(mode)` (`index.html:1961`) — единственное место переключения режима:

| Элемент | chat | orch | board |
|---|---|---|---|
| `#orch-bar` (Проект/Исполнитель/Резерв) | скрыт | виден | виден |
| `#messages` | виден | — | — |
| `#orch-messages` | — | виден | — |
| `#board` | — | — | виден |
| `#composer-wrap` | виден | виден | скрыт |
| `#model` (обёртка `.dd`) | виден | виден («Модель Оркестратора») | скрыт |

Режим сохраняется в `localStorage["edy-chat-mode"]` и восстанавливается при старте. Глобальная
переменная `msgsBox` указывает на активный контейнер сообщений (`#messages` или `#orch-messages`) —
все функции рендера сообщений пишут в него. История обычного чата и Оркестратора хранится раздельно,
так что переключение режимов не теряет переписку.

`#orch-bar` (`index.html:815-820`): `#project` (текущий проект, `localStorage["edy-project"]`),
`#worker` («Исполнитель»: модели + агенты команды; `edy-worker`), `#fallback` («Резерв (Circuit
Breaker)», `edy-fallback`), `#project-state` (текст состояния проекта: «идёт задача», «результат ждёт
решения…», «ветка X · готов», «⚠ проблема»).

`#new-chat`: в режиме Доска — фокус на поле новой задачи; в Оркестраторе — сбрасывает
`orchHistory`, `orchConversation`, `orchTaskID`; в Чате — прерывает поток и очищает `history_`.
Затем `showWelcome()`.

### 4.1. Режим «Чат» — прямой диалог с моделью через OmniRoute

- Приветствие `showWelcome()` с тремя чипами-примерами (клик = отправить).
- `send()` (`index.html:1573`):
  1. если режим orch → `sendOrch()`; если идёт поток (`abort != null`) — кнопка работает как «Стоп»;
  2. рисует сообщение пользователя (+ миниатюры картинок `.thumbs`), пушит в `history_`
     `{role:"user", content: messageContent(text)}` (строка или массив частей OpenAI);
  3. рисует пустой ответ бота с индикатором `.typing`;
  4. `fetch("/v1/chat/completions", {stream:true, messages: history_})` с заголовками
     `Authorization: Bearer`, `X-Edy-Client: chat` (по нему расход попадает в строку «chat» в «Расходах»);
  5. **разбор SSE** (`index.html:1601-1624`): читает `res.body.getReader()`, декодирует
     `TextDecoder` в потоковом режиме, копит буфер, режет по `"\n\n"`, берёт строки, начинающиеся с
     `data:`, пропускает `[DONE]`, парсит JSON; если в событии `error` — бросает ошибку; иначе
     добавляет `choices[0].delta.content` к ответу и перерисовывает `renderText`, прокручивая вниз;
  6. по окончании пушит ответ в `history_`; при `AbortError` («■») сохраняет частичный ответ и
     пишет «остановлено»; при другой ошибке удаляет вопрос из истории и показывает «⚠ …» с классом `.error`.
- `setBusy()` превращает кнопку отправки в красную «■ Остановить».
- `renderText(target, text)` (`index.html:1539`) — минимальная «разметка»: только блоки ```` ``` ````
  (первая строка-язык отрезается) → `pre > code`, и инлайн `` `код` `` → `code`. Всё остальное —
  текстовые узлы (никакого HTML, никакого Markdown-парсера).
- Клавиши: Enter — отправить, Shift+Enter — новая строка, учтён IME (`!e.isComposing`).
  Поле растёт до 180 px (`autosize`).

### 4.2. Режим «Оркестратор» — план → задача

- Приветствие: описание и до 5 чипов шаблонов задач (`templateList.custom` + `builtin`).
- `sendOrch()` (`index.html:1988`): вложения запрещены (тост: прикрепляйте скриншот к карточке на
  доске); нужен проект и модель. Первый вопрос создаёт `orchConversation` (`newConversation()` —
  случайный id, по нему бэкенд ведёт журнал агента-Оркестратора). Запрос:
  `POST /api/orchestrator {project, model, executors, messages: orchHistory, conversation}`, где
  `executors = pickExecutor().models` (Оркестратор видит возможности исполнителя и резерва).
  Ответ `r`: `text`, `plan`, `mcp[]`, `skills[]`, `new_mcp[]`, `subtasks[]`, `agent`.
  В историю ассистента план кладётся обратно обёрнутым в `<plan>…</plan>`.
- Под ответом:
  - `proposalCard(pr)` (`index.html:2027`) — на каждый `new_mcp`: «🆕 Оркестратор предлагает
    добавить MCP-сервер …», кнопка «Проверить и добавить в каталог» открывает `p-mcp` и через 300 мс
    заполняет форму (`fillMCPPreset`), секреты подставляются как `Authorization: Bearer <…>`;
  - `planCard(plan, project, mcp, skills, subtasks, agentName)` (`index.html:2069`) — блок `.plan`:
    текст плана; «👥 Ведёт агент команды: …», если Оркестратор отдал задачу агенту команды
    (и нет подзадач); «🧩 MCP для исполнителя: …»; «📘 Скиллы: …»; блок подзадач
    (`subtasksBlock`); кнопка «▶ Начать работу».
- `subtasksBlock(subtasks)` (`index.html:2044`) — если Оркестратор разбил задачу на эпик:
  строки `.subrow` с номером `.subnum`, названием, целью, зависимостями «после 1, 2» и select
  исполнителя (оптгруппы «Команда» — значения `agent:<имя>` — и «Модели»). Чекбокс «Сделать одним
  агентом, без деления» отменяет деление. Возвращает `{el, read()}`; `read()` отдаёт массив
  подзадач с выбранными `model`/`agent` (или `[]`).
- «▶ Начать работу»: `POST /api/tasks {id: orchTaskID, project, request (все реплики пользователя
  через \n), plan, comment, conversation, models, agent, subtasks}`. Если `orchTaskID` задан
  (обсуждали карточку из пула), запускается именно она. Затем `watchTask(v)`.
- `watchTask(v)` (`index.html:2105`) — карточка `.msg.bot.task` «Исполнитель · m1 → m2» со спиннером,
  заголовком состояния (`stateTitle`), кнопкой «Остановить» (`POST /api/tasks/{id}/cancel`) и лентой
  `.feed`. Опрос `GET /api/tasks/{id}?from=<n>` каждую секунду (инкрементально — сервер отдаёт
  события начиная с `from` и `next_from`), при ошибке — повтор через 2 с. События рисуются с иконкой
  из `kindIcon` и классом `k-<kind>` (`k-breaker` жёлтый жирный, `k-error` красный, `k-model` серый).
  Автопрокрутка только если пользователь был внизу («stick»).
- `showResult(t, box, title)` (`index.html:2141`) — по финальному состоянию:
  `done` → итог, модель, сырой diff в `pre`, кнопки «✓ Approve» / «✕ Reject — откатить»
  (`POST /api/tasks/{id}/approve|reject`; после approve — заметка и ссылка на PR, если есть);
  `needs_human`, `failed`, `cancelled` — пояснительный текст.

### 4.3. Режим «Доска» — канбан задач проекта

Разметка `#board` (`index.html:823-843`):
- `.board-bar`: форма `#board-new` (поле `request`, «＋ В пул» → `POST /api/board {project, request}`),
  `#tpl-btn` «📋 Шаблоны», `#issue-btn` «🔗 Из issue», переключатели `#board-auto` «Автопринятие»
  и `#board-notify` «🔔 Уведомления», кнопка `#notify-test` «Проверить».
- `#tpl-pop` — всплывающая панель шаблонов.
- `#board-cols` — пять колонок.

Колонки (`columns`, `index.html:2370`):

| id | Заголовок | Состояния задач | Drop-цель |
|---|---|---|---|
| `backlog` | 📥 Пул задач | backlog | да |
| `queued` | ⏳ Очередь | queued | да |
| `running` | ⚙️ В работе | running | нет |
| `review` | 👀 Ждёт решения | done, needs_human, failed | нет |
| `done` | ✅ Готово | approved, rejected, cancelled (последние 30 по `updated`) | нет |

Подзадачи эпика (`t.kind === "sub"`) в колонках не показываются — они внутри карточки эпика.

`loadBoard()` (`index.html:2384`): `GET /api/tasks?project=`, затем `GET /api/git/info?path=`
(для галочки «Автопринятие») и `GET /api/prefs` (для «Уведомлений»); `renderBoard()`; опрос
каждые 2 с, если есть running/queued, иначе 6 с — пока режим «Доска» активен.

Карточка `taskCard(t, byID, children)` (`index.html:2421`), `div.tcard`:
- «↳ родитель» для подзадач, заголовок, мета: состояние `.st.<state>` (`stateShort`), агент команды
  или первая модель, ревью (🔍 ✓ / замечания), число MCP/скиллов, бейдж «👥 эпик», прогресс
  подзадач «↳ x/y», «сколько назад» (`ago`);
- для эпика — полоска `epicBar(children)` (цвет сегмента по состоянию подзадачи);
- кнопки (с `stopPropagation`, чтобы не открывать карточку): backlog — «💬 С Оркестратором»
  (`discuss`) и «▶» (`enqueueRaw` — в очередь без плана); queued — «Снять» (cancel); running —
  «Остановить» (cancel); done — «✓ Approve» и «✕» (reject);
- `draggable` для backlog/queued/needs_human/failed/cancelled/rejected;
- клик — `openTask(id)` (модальная карточка, см. 5.2).

Drag-and-drop (`dropTask`, `index.html:2471`): перетаскиваемый id в `dragID`. Бросок в «Очередь»
задачи не из очереди → `enqueueRaw` (ставит с текущим Исполнителем из шапки). Бросок из очереди в
«Пул» → `cancel`. Бросок на другую карточку → `PUT /api/tasks/{id} {position: before.position - 1}`
(переупорядочивание).

Шаблоны (`index.html:2521-2563`): `GET /api/templates` → `{builtin[], custom[]}`. `renderTemplates()`
рисует чипы (свои — `.chip.custom`, правый клик — удалить `DELETE /api/templates?text=`) и чип
«＋ Текст из поля — в шаблоны» (`POST /api/templates {text}`). `useTemplate(t)` подставляет текст в
поле (на доске — `#board-new`, в Оркестраторе — `#input`) и **выделяет первый `{…}`**, чтобы
пользователь сразу его заменил.

Из issue (`#issue-btn`): `prompt()` со ссылкой → `POST /api/board/issue {project, url}` → задача в пул.

Автопринятие (`#board-auto`): читает текущие `git/info.settings`, меняет `auto_approve` и пишет
`PUT /api/git/settings` (то же поле, что в панели Git). При ошибке галочка откатывается.

Уведомления (`#board-notify`): `PUT /api/prefs {notify}`; `#notify-test` → `POST /api/notify/test`
(уведомление macOS через «Редактор скриптов» — см. тост).

`discuss(t)` (`index.html:2510`): закрывает модалку, включает Оркестратор, сбрасывает его историю,
запоминает `orchTaskID = t.id`, подставляет текст задачи в поле ввода. «Начать работу» в будущем
плане запустит именно эту карточку.

### 4.4. Композер: вложения, диктовка, голос

`#composer-wrap` (`index.html:844-855`): `#attach-row` (превью вложений), форма `#composer`:
📎 `#attach-btn`, скрытый `input#attach-file` (`accept` png/jpeg/gif/webp, `multiple`, `hidden`),
`textarea#input`, 🎤 `#dictate-btn`, 🎙 `#voice-btn`, ➤ `#send`.

**Картинки** (`index.html:1660-1716`):
- источники: кнопка 📎 (клик по скрытому input), вставка из буфера в `#input` (⌘V скриншота —
  `paste` с `clipboardData.files`), drag-and-drop файлов на `#composer-wrap` (класс `.drop` подсвечивает);
- `addImages(files)`: только `image/(png|jpeg|gif|webp)`, ≤5 МБ (`MAX_IMAGE = 5<<20`), ≤4 за
  сообщение; читаются в data-URL (`readAsDataURL`) и копятся в `pending.images`;
- `renderPending()` — миниатюры с ✕;
- при отправке `messageContent(text)` собирает массив частей OpenAI:
  `{type:"text"}`, `{type:"image_url", image_url:{url:"data:…"}}`,
  `{type:"input_audio", input_audio:{data:<base64>, format:"wav"}}`. Без текста подставляется
  «Что на изображении?» или «(голосовое сообщение)». Подходит ли модель (теги «Картинки»/«Звук»),
  проверяет OmniRoute и сам возвращает понятную ошибку;
- `showImage(src)` — лайтбокс `.lightbox` (клик закрывает).

**Диктовка** 🎤 (`index.html:1721-1750`) — Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`),
`lang = ru-RU`, `continuous`, `interimResults`. Текст пишется прямо в `#input`: исходный текст +
финальные + промежуточные результаты. Повторный клик — стоп. Без API — тост с советом использовать
системную диктовку macOS (дважды Fn). Ошибки `no-speech`/`aborted` молча игнорируются,
`not-allowed` → «нет доступа к микрофону». Никаких запросов к моделям и токенов.

**Голосовое сообщение** 🎙 (`index.html:1754-1813`) — запись для моделей с тегом «Звук»:
`getUserMedia({audio:true})` → `AudioContext` → `ScriptProcessorNode(4096,1,1)` копит `Float32Array`
чанки; лимит 120 с (`setTimeout`). Повторный клик — стоп: отключение узлов, остановка треков,
`encodeWAV(chunks, sampleRate)` → PCM 16 бит моно 16 кГц (понижение частоты простым прореживанием,
без фильтра) → base64 в `pending.audio = {data, seconds}`. Кнопка в режиме записи — класс `.tool-btn.on`
(красная пульсация).

### 5.2. Карточка задачи — `openTask(id)` (`index.html:2612`)

`GET /api/tasks/{id}` → полное представление задачи с событиями. Содержимое сверху вниз:

1. Заголовок, состояние `.st`, ✕. Для подзадачи — ссылка «Подзадача к: <родитель>».
2. Кнопки действий (зависят от состояния): backlog — «💬 Обсудить с Оркестратором», «▶ В очередь
   без плана»; needs_human/failed/cancelled/rejected — «↻ Ещё раз с Оркестратором»; queued — «Снять с
   очереди»; running — «Остановить»; done — «✓ Approve — принять», «✕ Reject — откатить»; всё, что
   не running/done — «Удалить» (`DELETE /api/tasks/{id}`).
3. Ссылка на issue + пояснение, что коммит после Approve закроет issue (`issue_ref`).
4. «Задача» — текст запроса.
5. «Скриншоты (N)» — `attachmentGallery(t)` (`index.html:1816`): картинки грузятся
   `fetch(/api/tasks/{id}/attachments/{file})` с токеном → `blob:` URL (поэтому в CSP нужен `blob:`),
   ✕ → `DELETE …/attachments/{file}`; «📎 Прикрепить скриншот» → скрытый `input[type=file]` →
   `POST /api/tasks/{id}/attachments {name, data: dataURL}`. Пока карточка открыта, ⌘V с картинкой
   в любом месте модалки загружает её (`index.html:1847-1851`, через `gallery.upload`).
6. «План Оркестратора».
7. «Исполнитель» — модели (вторая и далее — «резерв:»), MCP, скиллы; если вёл агент команды — его имя.
8. «Итог» (summary + модель).
9. «Ревью · модель» — блок `.review.ok|issues`; при замечаниях кнопка «🧩 Замечания → подзадача»
   (`POST /api/board {parent: id, title: "Замечания ревью: …", request}`).
10. «Ошибка».
11. «Изменения» — `diffView(t)` (`index.html:2698`): `GET /api/tasks/{id}/patch` →
    `diffViewer(patch, {project, onRevert})`; откат отдельного файла доступен только в состоянии
    `done` → `POST /api/tasks/{id}/revert-file {file}`. Если патч не получен — сырой `t.diff` в `pre.log`.
12. «Результат» — заметка после Approve, ссылка на PR.
13. Для эпика — «Агенты эпика (N)»: строки подзадач (шаг, ссылка, агент/модели, зависимости, ошибка,
    состояние). Для обычной задачи — «Подзадачи (N)» + форма «Новая подзадача»
    (`POST /api/board {project, parent, title, request}`).
14. «История» — таймлайн `.timeline > .tl.k-<kind>` с датой и иконкой; форма комментария →
    `POST /api/tasks/{id}/comment {text}`.

Пока задача `running`/`queued` и модалка открыта — перерисовка каждые 3 с (`taskTimer`).

### 7.1. Помощники

- **`token`** (`874`) — IIFE: хэш → `sessionStorage["edy-token"]` (+ `edy-app`), очистка хэша.
- **`store`** (`885`) — обёртка `localStorage` с `try/catch` (в приватном режиме/WebView без
  хранилища не падает). Ключи: `edy-panel`, `edy-model`, `edy-worker`, `edy-fallback`,
  `edy-project`, `edy-chat-mode`.
- **`$(sel, root)`** (`890`) — `querySelector`.
- **`el(tag, attrs, ...children)`** (`891`) — фабрика DOM:
  - `class` → `className`; ключи на `on…` → `addEventListener` (например `onclick`, `onsubmit`);
    остальное → `setAttribute` (поэтому `hidden: ""` работает как булев атрибут);
  - дети: `Node` вставляется как есть, **всё прочее — через `document.createTextNode`** (включая
    `null/undefined` → пустая строка). Это главный механизм защиты от XSS (раздел 11).
  - Пустая строка `""` как ребёнок — удобный способ «ничего не вставлять» в условных выражениях:
    `cond ? el(...) : ""`.
- **`money(v)`** — `$0.0012` для сумм < 1 цента, иначе 2 знака. **`num(v)`** — `ru-RU` разделители.
- **`toast(msg, isError)`** (`904`) — `div.toast` внизу; несколько подряд встают стопкой
  (смещение 54 px); живут 2,5 с (ошибки — 6 с).
- **`api(method, path, body)`** (`913`) — `fetch` с `Authorization: Bearer <token>`, JSON-телом;
  204 → `null`; при `!res.ok` бросает `Error` с текстом `data.error.message || data.error ||
  "Ошибка <status>"` и полями `err.status`, `err.data` (используется, например, для 409 + `install`).
  Соглашение: вызывающий код ловит ошибку и показывает `toast(e.message, true)`.

### 7.5. Модели и исполнители

- `chatModels()` (`1491`) — все `provider/model`, **кроме** моделей с `embed` в имени
  (эмбеддинги нужны только для поиска по смыслу).
- `fillModels()` (`1495`) заполняет три select'а:
  - `#model` — модели (для чата и Оркестратора), ключ `edy-model`;
  - `#worker` — оптгруппа «Команда проекта» (`agent:<id>`, только `enabled`) + оптгруппа «Модели»;
    у моделей провайдеров с `p.mcp` суффикс « · MCP»; ключ `edy-worker`;
  - `#fallback` — «— нет» + модели (агенты команды тоже не добавляются, т.к. передан `empty`); `edy-fallback`.
  Текущее значение сохраняется, если оно ещё существует.
- `pickExecutor()` (`1866`) превращает выбор в `{agent, models}`: агент команды → его `model` и
  `fallback` (без дублей); иначе `[worker, fallback]` (fallback игнорируется, если совпадает или это агент).
- `executors()` (`2382`) — короткий доступ к `pickExecutor().models`.

### 7.6. Подсветка кода (`index.html:2174-2273`)

Свой лёгкий токенизатор — внешние библиотеки запрещены CSP и требованием офлайн-работы.

- `LANGS` — описания языков: `kw` (ключевые слова), `types`, `lit` (литералы), `line`
  (однострочный комментарий), `block` (`[open, close]`), `str` (разделители строк, проверяются по
  порядку — поэтому `"""` раньше `"`), `nocase` (SQL), `markup` (HTML).
- **Поддерживаемые языки:** `go`, `py`, `js`, `ts` (= js), `json`, `sh`, `yaml`, `toml`, `css`, `sql`,
  `rust`, `c` (C/C++), `java` (Java + ключевые слова Kotlin), `swift`, `md` (только `` ` ``-строки),
  `html` (markup: теги, атрибуты, строки, `<!-- -->`).
- `EXT` — расширения → язык: go, py, js/mjs/cjs/jsx, ts/tsx, json, sh/bash/zsh, yml/yaml, toml,
  css/scss, sql, rs, c/h/cc/cpp/hpp, java/kt, swift, md, html/htm/xml/vue/svelte. Особые имена:
  `Dockerfile`, `Makefile`, `*.env` → sh. Неизвестное — без подсветки.
- `tokenize(code, lang)` → массив `[класс, текст]`: комментарии → `hl-com`; теги → `hl-tag`,
  атрибуты → `hl-attr`; строки → `hl-str` (обратный слэш экранирует только в однобуквенных
  кавычках кроме `` ` ``; однобуквенная строка обрывается на переводе строки); числа (dec/hex/exp,
  не после идентификатора) → `hl-num`; слова → `hl-kw`/`hl-type`/`hl-lit`, а если сразу за словом `(` —
  `hl-fn`.
- `highlightLines(code, lang)` — массив HTML-строк по строкам исходника (многострочный комментарий
  корректно «переносится» в следующие строки). Текст экранируется `esc()`.
- `codeTable(text, file)` — `div.code > table` с номерами строк (`innerHTML`).

### 7.7. Просмотр diff (`index.html:2275-2332`)

- `parsePatch(patch)` — разбор unified diff: файлы по `diff --git … b/<path>`, статус
  (`new file mode` → «новый», `deleted file mode` → «удалён», `rename to` → «переименован»,
  `Binary files` → двоичный), ханки `@@ -a,b +c,d @@` с подсчётом номеров старых/новых строк,
  строки `+`/`-`/` `, счётчики `add/del`. Строки `\ No newline…` пропускаются.
- `diffViewer(patch, {project, onRevert})` — шапка «N файл(ов) · +X −Y»; на каждый файл
  `<details class="dfile">` (открыты, если файлов ≤ 6) с бейджем статуса, счётчиками, кнопками
  «Открыть» (в просмотрщике файлов) и «↩ Откатить файл» (если передан `onRevert`); таблица из
  4 колонок: старый №, новый №, знак, код с подсветкой (каждая строка подсвечивается отдельно).

### 7.8. Свои выпадающие списки (`index.html:3144-3292`)

Зачем: системный список `<select>` в macOS/WKWebView не стилизуется CSS и выбивается из дизайна.

Как устроено:
- `enhance(sel)` оборачивает **каждый** `select` (кроме `multiple` и уже обёрнутых) в
  `span.dd`, сам select становится невидимым (`opacity:0; pointer-events:none`, `tabIndex=-1`), но
  **остаётся в форме** — значение, `form.elements`, события `change` работают как раньше. Рядом
  кнопка `button.dd-btn` с `span.dd-label` и SVG-шевроном.
- `sync(dd)` — текст кнопки = текст выбранной опции; класс `.ph`, если value пустое; `disabled`
  и `hidden` копируются с select.
- Синхронизация срабатывает: по `MutationObserver` на select (смена опций/атрибутов), по `change`,
  по `reset` формы и — **хак** — через переопределение сеттеров `HTMLSelectElement.prototype.value`
  и `selectedIndex` (`index.html:3277-3282`): присваивание `sel.value = …` из кода не порождает
  событий, а надпись должна обновиться.
- Новые select'ы, добавленные в DOM позже (например, в `subtasksBlock`, в `fillAgentForm`),
  подхватываются глобальным `MutationObserver` на `document.body` (`index.html:3286-3291`).
- `show(dd)` создаёт `ul.dd-list` в `body` (`position: fixed`, z-index 1000), рендерит опции и
  оптгруппы (`.dd-group`), позиционирует (`place`: вниз или вверх, если снизу < 220px и сверху
  больше места; ширина от ширины кнопки до 460px).
- `choose(dd, o)` ставит `sel.value` и диспатчит `input` и `change` (bubbles) — поэтому обычные
  обработчики `change` на select работают.
- Клавиатура (капчер-обработчик на document): ↑/↓, Home/End, Enter/Space — выбрать, Escape —
  закрыть, Tab — закрыть, буква — переход к опции на эту букву. Мышь: `mousedown` вне — закрыть;
  `resize` и скролл вне списка — закрыть.
- Отметка выбранной опции — **CSS-галочка** (`.dd-opt.sel::before` — повёрнутая рамка, `index.html:333`),
  а не SVG в `data:`-URL (раньше CSP блокировал такую картинку — см. 13).

Следствия для разработчика:
- Видимость select'а меняйте через `sel.hidden` у **самого select** или через обёртку
  (`sel.parentElement` — это `.dd`); `$("#model").parentElement.hidden` в `setChatMode` прячет именно обёртку.
- Не ставьте CSS-ширину на select — ставьте на `.dd` (см. `.chat-head .dd`, `.orch-bar .dd`,
  `#mem-add .dd`, `.subrow .dd`).

### 7.9. Окно Wails (`index.html:929-940`)

Если `sessionStorage["edy-app"] == "1"`, на `<html>` вешается класс `in-app` (в CSS пока не
используется) и перехватываются клики по внешним ссылкам `a[href^='http']` с другим origin:
вместо навигации — `POST /api/open {url}` (сервер принимает только http/https), Edy открывает ссылку
в системном браузере.

## 11. Безопасность

### 11.1. Заголовки (`internal/ui/ui.go`)

```
X-Frame-Options: DENY
Content-Security-Policy: default-src 'self';
  script-src 'self' 'unsafe-inline';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  media-src 'self' data: blob:;
  frame-ancestors 'none'
```

- `script-src 'self' 'unsafe-inline'` — `'unsafe-inline'` нужен, потому что весь JS встроен в
  страницу. **Внешних скриптов нет и быть не может** (CDN заблокирован политикой) — поэтому, например,
  подсветка кода написана вручную.
- `img-src data: blob:` — превью вложений (`data:` URL из `FileReader`) и картинки задач
  (`URL.createObjectURL(blob)`). `media-src data: blob:` — на случай воспроизведения записанного звука.
- `connect-src` не задан → наследует `default-src 'self'`: `fetch` возможен только к своему origin.
  Интерфейс не может обратиться ни к какому внешнему сервису напрямую — всё через бэкенд.
- `frame-ancestors 'none'` + `X-Frame-Options: DENY` — защита от clickjacking.
- Шрифты — системные, внешних нет.
- Встроенный SVG-шеврон в `.dd-btn` вставлен как inline-SVG через `innerHTML` (не картинка) — на него
  `img-src` не действует.

### 11.2. Токен

- Хранится в `sessionStorage` (живёт до закрытия вкладки), не в `localStorage`; из адресной строки
  стирается сразу.
- Все `/api/*` требуют Bearer — чужой сайт, открытый в том же браузере, не может управлять Edy
  через localhost (CORS-запрос без токена получит 401; токен ему неизвестен).
- В «Подключении» токен скрыт точками; в сниппете HTTP-MCP показывается `<токен>`, а реальный
  подставляется только при копировании.
- Значения секретов (API-ключи, токены git, заголовки/env MCP) сервер в интерфейс **не отдаёт** —
  показываются только метки/имена.

### 11.3. Экранирование (проверено)

- `el()` вставляет всех детей-не-узлов через `document.createTextNode` (`index.html:898`), а атрибуты —
  через `setAttribute`. Поэтому любые строки с сервера (ответы моделей, имена файлов, тексты задач,
  описания MCP) **не интерпретируются как HTML**.
- `renderText()` строит `pre/code` через `el()` — ответы моделей безопасны.
- `toast()` — тоже через `el()`.
- `innerHTML` используется только в четырёх местах:
  1. `index.html:1163` — статичная разметка кнопки dd + константный SVG;
  2. `codeTable` (`2271`) — номера строк + результат `highlightLines`, где **каждый** кусок текста
     прошёл `esc()`; классы — константы из токенизатора;
  3. `diffViewer` (`2313-2321`) — заголовок ханка и знак через `esc()`, код через `highlightLines`;
  4. `diffViewer` двоичный файл — статичный текст.
  `esc()` экранирует `& < > "` (не `'`) — достаточно, т.к. в атрибуты динамика не попадает.
- `textContent` используется для всех текстовых полей (`#ctx-out`, `#sem-status`, `.dd-label` и т.д.).

### 11.4. Остаточные риски

- `href` у ссылок на PR / issue / страницу ключа берётся из данных сервера (`r.pr_url`, `t.issue_url`,
  `pr.key_url`) через `setAttribute`. При `script-src 'unsafe-inline'` ссылка `javascript:…`
  выполнилась бы по клику. Сейчас эти URL генерирует сам бэкенд (git-хостинг, встроенные пресеты),
  поэтому риск низкий, но при появлении ссылок из пользовательского/модельного ввода стоит
  проверять схему (`http(s)` only) — по образцу `POST /api/open`.
- `confirm()`/`prompt()` в WKWebView (Wails v2, macOS) диалог не показывают и сразу возвращают
  `false`/`null`, поэтому не используются: вместо них свой модальный `#ask-modal` —
  `askDialog`/`askConfirm`/`askPrompt` (Promise; Enter — подтвердить, Escape/фон — отмена).

## 12. Как тестировать интерфейс (Playwright)

Автотестов интерфейса в репозитории **нет**. Принятая практика — ручной прогон через Playwright
со скриншотами против временного dev-сервера. Ниже — паттерн, которым пользовались при разработке.

### 12.1. Временный dev-сервер `cmd/devui/main.go`

Идея: поднять настоящий `app.Start` (весь Edy: OmniRoute + API + UI) на фиксированном адресе с
фиксированным токеном, с базой во временной папке, с фальшивыми провайдерами на `httptest`.
Keychain не нужен — мастер-ключ хранилища задаётся напрямую (`vault.New`), как в
`internal/app/app_test.go`.

```go
// cmd/devui/main.go — ВРЕМЕННЫЙ файл, удалить перед коммитом!
package main

import (
	"bytes"
	"fmt"
	"io"
	"log"
	"net/http"
	"net/http/httptest"
	"os"
	"path/filepath"
	"strings"

	"github.com/laurenwilcox/name/internal/app"
	"github.com/laurenwilcox/name/internal/store"
	"github.com/laurenwilcox/name/internal/vault"
)

func main() {
	home, _ := os.MkdirTemp("", "edy-devui-")
	v, _ := vault.New(bytes.Repeat([]byte{7}, 32))
	st, err := store.Open(filepath.Join(home, "edy.db"), v)
	if err != nil {
		log.Fatal(err)
	}
	// Фиксированный токен: app.Start возьмёт его из настройки router_token.
	st.SetSetting("router_token", "edy-devtoken")

	// Фальшивый OpenAI-совместимый провайдер.
	fake := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		switch {
		case strings.HasSuffix(r.URL.Path, "/models"):
			fmt.Fprint(w, `{"data":[{"id":"fake-chat"},{"id":"fake-embed"}]}`)
		case strings.Contains(string(body), `"stream":true`):
			w.Header().Set("Content-Type", "text/event-stream")
			for _, part := range []string{"Привет", "! Это ", "`код`"} {
				fmt.Fprintf(w, "data: {\"choices\":[{\"delta\":{\"content\":%q}}]}\n\n", part)
			}
			fmt.Fprint(w, "data: [DONE]\n\n")
		default:
			fmt.Fprint(w, `{"choices":[{"message":{"role":"assistant","content":"Ответ"}}],"usage":{"prompt_tokens":5,"completion_tokens":3}}`)
		}
	}))
	defer fake.Close()
	st.AddProvider(store.Provider{Name: "fake", Kind: store.KindOpenAI, BaseURL: fake.URL + "/v1",
		Models: []string{"fake-chat", "fake-embed"}})

	srv, err := app.Start(st, home, "127.0.0.1:18080", nil)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("UI:", srv.URL(), "home:", home)
	<-srv.Done()
}
```

Замечания:
- Проект для панелей «Проект»/«Git»/«Доска» удобно добавить уже через API из теста
  (`POST /api/projects {path}`) — например, `git init` во временной папке с одним коммитом.
- Ответ фальшивого провайдера подгоняйте под то, что реально ждёт адаптер OmniRoute
  (`internal/omniroute`); пример выше — минимальный.
- Для задач/доски без реального исполнителя можно наполнять доску через `POST /api/board`
  (задачи в пуле не требуют моделей).

Запуск (в фоне): `go run ./cmd/devui &` → в логе `UI: http://127.0.0.1:18080/#token=edy-devtoken`.

})();

Посмотреть скриншоты можно инструментом чтения изображений (Read по PNG) — так проверяют вёрстку
в обеих темах.

### 12.3. Обязательная уборка

**Папку `cmd/devui` удалять перед каждым коммитом** (`rm -rf cmd/devui`), а dev-сервер — останавливать.
Она не должна попасть в репозиторий: в ней фиксированный токен и фальшивые провайдеры, и она
ломает идею «`go build ./...` собирает только продуктовые команды». Скриншоты и скрипт Playwright
тоже в репозиторий не кладутся. Перед коммитом: `git status` — в изменениях не должно быть
`cmd/devui/`, `*.png`, `ui-check.js`.

### 12.4. Что ещё проверять вручную

- консоль без ошибок в обеих темах;
- узкий экран (`viewport: {width: 420, height: 860}`): ☰, шторка меню, панель на весь экран;
- клавиатура в выпадающих списках (↑↓ Enter Escape, буквы);
- что после `sel.value = …` из кода надпись на `.dd-btn` обновилась;
- CSP: ошибки вида `Refused to load…` в консоли означают, что вы добавили внешний ресурс.

## 13. Известные ограничения, подводные камни, найденные баги

### 13.1. Подводные камни при разработке и тестах

- **Скрытый file input** (`#attach-file` с атрибутом `hidden`, а в карточке задачи — динамический
  `input` с `pick.hidden = true`): `waitForSelector` по умолчанию ждёт `visible` и зависнет —
  используйте `{ state: "attached" }`; `setInputFiles` на скрытом input работает.
- **Нативные select'ы скрыты** (`opacity:0; pointer-events:none`). `page.selectOption("#model", …)`
  обычно работает (опасити 0 Playwright считает видимым), а клик по select — нет. Для проверки
  именно UI кликайте `.dd-btn`, затем `li.dd-opt` с нужным текстом (список висит в `body`, не внутри `.dd`).
- **CSP и `data:`-картинки в CSS.** Галочка выбранной опции в выпадающем списке раньше была SVG в
  `data:`-URL и блокировалась CSP (тогда в `img-src` не было `data:`). Сейчас галочка нарисована
  чистым CSS (`.dd-opt.sel::before`, `index.html:333`). Правило: не добавляйте внешние картинки/шрифты;
  иконки — эмодзи, inline-SVG или CSS.
- **`[hidden] { display:none !important }`** — если элемент «не показывается», проверьте атрибут
  `hidden`, а не CSS.
- **Анимации**: панель выезжает 0,45 с, карточки появляются через `rise` — перед скриншотом ждите
  ~0,5 с или эмулируйте `reducedMotion: "reduce"` в контексте Playwright.
- **Номера строк в этом документе** устаревают при каждой правке `index.html`.
- **Нет горячей перезагрузки**: файл встраивается при компиляции — после правки перезапускайте dev-сервер.
- `setChatMode` прячет `$("#model").parentElement` — это обёртка `.dd`. Если когда-нибудь убрать
  свои выпадающие списки, этот код спрячет всю `.chat-head`.

### 13.2. Ограничения

- Тема только системная, переключателя нет.
- `renderText` поддерживает только код-блоки и инлайн-код; Markdown (заголовки, списки, ссылки,
  жирный) показывается как есть.
- История чата и Оркестратора живёт только в памяти вкладки — перезагрузка её теряет (кроме журнала
  агентов на сервере и задач на доске).
- Подвал меню «OmniRoute работает» — статичный текст, реальное здоровье сервера не проверяется.
- Диктовка зависит от Web Speech API: в Chrome работает (через облако Google), в WKWebView окна Wails
  обычно недоступна → подсказка про системную диктовку macOS.
- Запись голоса: `ScriptProcessorNode` устарел (рекомендуется `AudioWorklet`); понижение частоты
  без фильтра даёт алиасинг; максимум 120 с; формат только WAV.
- Вложения: ≤4 картинки по ≤5 МБ на сообщение; Оркестратору вложения не передаются вовсе.
- Список файлов в просмотрщике — до 1500, моделей в редакторе — до 400, «Готово» на доске — последние 30,
  память — до 60 заметок.
- Подсветка — эвристическая (нет regex-литералов JS, шаблонных подстановок `${}`, вложенных
  комментариев Rust/Swift, heredoc в shell и т.п.).

### 13.3. Найденные баги и странности (на момент написания)

1. **Пояснение Оркестратора к плану никогда не сохраняется.** `planCard` берёт комментарий как
   `box.closest(".msg")?.querySelector(".body")?.innerText` (`index.html:2085`), но `addMessage`
   создаёт тело сообщения как `el("div")` **без класса `body`** (`index.html:1557`). В итоге в
   `POST /api/tasks` всегда уходит `comment: ""`, и бэкенд (`internal/api/projects.go:569-570`)
   не добавляет в историю задачи комментарий «Оркестратор». Исправление: `el("div", {class: "body"})`
   в `addMessage` (проверить, что CSS `.body` нигде не мешает — сейчас такого класса нет).
2. **Опрос `watchTask` не останавливается**, когда пользователь нажал «＋ Новый» или очистил чат:
   карточка удалена из DOM, а `poll` продолжает дёргать `GET /api/tasks/{id}` до финального
   состояния задачи. Безвредно, но лишняя нагрузка; кнопки Approve/Reject при этом пропадают из чата
   (остаются на доске).
3. **`loadBoard` на каждом тике опроса делает три запроса** (`/api/tasks`, `/api/git/info`,
   `/api/prefs`) и перезаписывает галочки `#board-auto`/`#board-notify` — если пользователь кликнул
   галочку во время запроса, её состояние может «прыгнуть» назад до следующего тика. `git/info`
   вдобавок запускает git-команды на сервере каждые 2–6 с.
4. **`attachmentGallery` не проверяет `res.ok`** (`index.html:1822-1823`): при ошибке сервера JSON
   ошибки превращается в blob и показывается битой картинкой вместо подписи.
5. **Необработанные промисы**: удаление заметки в `agentMemory` (`index.html:1940`) и удаление
   шаблона по правому клику (`index.html:2550`) не обёрнуты в `try/catch` — при ошибке API пользователь
   ничего не увидит, в консоли — `Uncaught (in promise)`.
6. **Escape закрывает и выпадающий список, и модалку одновременно**: обработчик dd на document
   (capture) делает `preventDefault`, но не `stopPropagation`, а обработчик модалок (`index.html:2606`)
   проверяет только `e.key`. Сейчас внутри модалок нет select'ов, поэтому не проявляется, но
   появится, если добавить select в карточку задачи.
7. **Перетаскивание в «Очередь»** ставит задачу с **текущим** Исполнителем из шапки, а не с моделями,
   с которыми задача шла раньше (для failed/rejected это может быть неожиданно).
8. **Переупорядочивание**: `position: before.position - 1` может совпасть с позицией соседней
   карточки — порядок при равных позициях не определён.
9. Класс `in-app` на `<html>` ставится, но ни одно CSS-правило его не использует.
10. Агенты команды в `#worker` хранятся как `agent:<id>`, а в селектах подзадач (`subtasksBlock`) —
    как `agent:<имя>`. Это **не баг** (бэкенд для подзадач ждёт имя — `internal/orchestrator/orchestrator.go:106`),
    но легко перепутать.
11. В `loadAgents` при `a.goal == null` упадёт `a.goal.split` (сервер сейчас всегда отдаёт строку).
12. `send()`: разбор SSE режет только по `"\n\n"` (не `"\r\n\r\n"`) и делает `JSON.parse` без защиты —
    нестандартная строка `data:` оборвёт поток ошибкой. Сервер свой, так что на практике не проявляется.

## 14. Как добавить новую панель — по шагам

Пример: панель «Расписание» с id `p-sched`.

1. **Пункт меню** в `nav#side` (`index.html:431-449`):
   ```html
   <button class="menu-item" data-open="p-sched"><span class="ico">⏰</span>Расписание</button>
   ```
   Для пункта внутри группы «Провайдеры» — добавить в `.submenu > div` без иконки (тогда он получит
   подсветку `.active`).
2. **Секция** внутри `.panel-body` (рядом с остальными, `index.html:459-798`):
   ```html
   <section id="p-sched">
     <div id="sched-list"></div>
     <form class="card form-grid" id="sched-form">
       <label>Имя <input name="name" required autocomplete="off"></label>
       <label>Когда <select name="when"><option value="daily">ежедневно</option></select></label>
       <div class="row wide"><button class="btn" type="submit">Сохранить</button></div>
     </form>
   </section>
   ```
   Секцию не нужно прятать атрибутом `hidden` — `openPanel` прячет все неактивные секции сам. Но
   **до первого открытия** любой панели все секции видимы внутри закрытого drawer (ширина 0) — это нормально.
   Select внутри будет автоматически превращён в свой выпадающий список.
3. **Заголовок и загрузчик** — добавить в словари `titles` и `loaders` (`index.html:943-944`):
   ```js
   titles["p-sched"] = "Расписание";   // или прямо в литерал объекта
   loaders["p-sched"] = loadSched;
   ```
   Без записи в `loaders` `openPanel` упадёт (`loaders[id] is not a function`), без `titles` —
   панель не восстановится после перезагрузки (`if (last && titles[last])`).
4. **Загрузчик** — по общему шаблону:
   ```js
   async function loadSched() {
     let list;
     try { list = await api("GET", "/api/sched?project=" + encodeURIComponent($("#project").value)); }
     catch (e) { return toast(e.message, true); }
     $("#sched-list").replaceChildren(...(list.length
       ? list.map((s, i) => el("div", { class: "card lift", style: `animation-delay:${i * 60}ms` },
           el("div", { class: "row spread" }, el("strong", {}, s.name),
             el("button", { class: "btn danger icon", onclick: async () => {
               if (!(await askConfirm(`Удалить «${s.name}»?`))) return;
               try { await api("DELETE", "/api/sched/" + s.id); loadSched(); } catch (e) { toast(e.message, true); }
             } }, "Удалить"))))
       : [el("div", { class: "card empty" }, "Пока пусто.")]));
   }
   $("#sched-form").addEventListener("submit", async (e) => {
     e.preventDefault();
     const f = e.target;
     try { await api("POST", "/api/sched", { name: f.name.value.trim(), when: f.when.value }); f.reset(); toast("Сохранено"); loadSched(); }
     catch (err) { toast(err.message, true); }
   });
   ```
   Правила: строить DOM только через `el()` (никакого `innerHTML` с данными); каждый `api()` — в
   `try/catch` с `toast(e.message, true)`; пустое состояние — `.card.empty` или `.muted.small`.
5. **Зависимость от проекта**: если панель показывает данные текущего проекта — добавьте её
   перерисовку в обработчик `change` у `#project` (`index.html:2727`) по образцу
   `if ($("#drawer").classList.contains("open") && !$("#p-git").hidden) loadGit();`.
6. **Опрос** (если нужен): `let schedTimer`; в начале загрузчика `clearTimeout(schedTimer)`; в конце —
   `if ($("#drawer").classList.contains("open") && !$("#p-sched").hidden) schedTimer = setTimeout(loadSched, 5000);`.
7. **Бэкенд**: эндпоинты — в `internal/api` (регистрация `m.HandleFunc("GET /api/sched", …)`),
   обязательно за Bearer-проверкой общего `Handler`. Описать их в `05-api.md`.
8. **CSS**: использовать существующие компоненты (`.card`, `.form-grid`, `.btn`, `.badge`, `.status`).
   Новые цвета — только через токены и `color-mix`; проверить обе темы.
9. **Проверка**: dev-сервер + Playwright (раздел 12), скриншоты светлой и тёмной темы, консоль без
   ошибок, узкий экран. Удалить `cmd/devui` перед коммитом.
10. **Документация**: обновить этот файл (разделы 3, 8, 9, 10) и `docs/ARCHITECTURE.md`.
